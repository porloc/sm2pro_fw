## КОНТЕКСТ (что уже известно)

Адаптер: клон Scanmatik 2 Pro, STM32F105VCT6, 256KB flash, 64KB RAM.
Карта flash: bootloader 0x08000000 (12KB, не обновляется), EEPROM-эмуляция
0x08002800 (страница A, магия 0x5AA5 @0x08002FFE) + 0x08003000 (страница B),
stage2 0x08004000, приложение 0x08005000 (у 2.22.3 — с векторной таблицей,
main @0x0800B7F0, вход 0x08005164).

Проблема: прошивка 2.22.3 (новая архитектура, новый протокол) не работает с ПО
Scanmatik 2.22.3 на клоне (PID 0x0001). При патче PID→0x0002 ПО начинает новую
авторизацию и падает с «Внутренняя ошибка микропрограммы 29CD744C».

Механизм авторизации в прошивке 2.22.3 — обработчик команды 0x103 @ **0x08007E60**:
- [R0+1] (полуслово) должно быть 0x103;
- [R0+4] = 0x00 → чтение крипто-таблицы (EEPROM-регистры 0x38..0xB8, 128×16бит,
  физически flash 0x08002870..0x08002970);
- [R0+4] = 0x99 → запись таблицы + верификация, при несовпадении возвращает 0x20.
Сервисы bootloader: чтение/запись EEPROM через вызов по указателю [0x0800017C]
(диспетчер 0x080002CC, r0=номер сервиса, r1=указатель на слово-параметр).
Сервис 7 = build ID, сервис 8 = ключ по индексу из 0x08000184+.

Смежные точки: G @0x0800722C (кластер 0xAC, берёт build ID и 3 ключа сервисами
7/8, вызывает VM-криптофункцию F @0x0800C15C), main @0x0800B7F0.

## ЧТО НУЖНО СДЕЛАТЬ (по порядку)

### ЭТАП 0. Бэкап (обязательно!)
```
J-Link> device STM32F105VC
J-Link> si SWD
J-Link> speed 1000
J-Link> connect
J-Link> h
J-Link> savebin backup_before_auth_test.bin, 0x08000000, 0x40000
```
Пришли файл backup_before_auth_test.bin (выгрузи в GitHub-репозиторий
porloc/sm2pro_fw в папку dumps/ или дай ссылку).

### ЭТАП 1. Снимок активной авторизации (самое важное!)
Условие: на адаптере залит патченный образ firmware_2.22.3_AUTH_TABLE+PID2.bin
(из репозитория, patched/) — PID 0x0002 + заполненная крипто-таблица из 2.21.35.

1. Подключи J-Link, останови ядро, поставь аппаратный breakpoint:
```
J-Link> h
J-Link> ClrBP 1
J-Link> ClrBP 2
J-Link> SetBP 0x08007E60
J-Link> mem16 0x08007292, 1        ; убедиться, что там 0xB118 (не 0xBE00!)
J-Link> g
```
2. Запусти ПО Scanmatik 2.22.3, дождись останова на 0x08007E60.
3. При останове сними ВСЁ:
```
J-Link> regs
J-Link> mem32 0x20000000, 0x40
; R0 = указатель на пакет команды 0x103. Дампни 0x120 байт от R0:
J-Link> savebin cmd103_packet.bin, <ЗНАЧЕНИЕ_R0>, 0x120
; и весь RAM-снимок:
J-Link> savebin ram_at_auth.bin, 0x20000000, 0x10000
J-Link> g
```
4. Повтори пункт 3 для КАЖДОЙ остановки на 0x08007E60 (авторизация может
   вызываться несколько раз: чтение, запись, повторное чтение). Сохрани все
   снимки (cmd103_packet_N.bin, ram_at_auth_N.bin).
5. Если ПО покажет ошибку/успех — зафиксируй текст и код.

Цель: увидеть содержимое пакета 0x103 от ПО (что ПО пишет в таблицу и что
ожидает прочитать) и параметры верификации.

### ЭТАП 2. Трассировка ошибки 29CD744C
Если на этапе 1 ПО упало с «Внутренняя ошибка микропрограммы 29CD744C»:
1. Дополнительно поставь BP на точку возврата ошибки верификации:
```
J-Link> SetBP 0x08007F50        ; здесь r6=0x20 при провале верификации
```
2. При останове: regs + mem32 по R4 (страница EEPROM) — сравни содержимое
   0x08002870..0x08002970 с ожидаемой таблицей из пакета (Этап 1).
3. Проверь, куда уходит запись при не-0xFFFF остатках: BP 0x08001B56 (запись
   в запасную страницу) — если ПО пишет в страницу B (0x08003000), а чтение
   идёт из A (0x08002800) — вот и причина провала верификации.

### ЭТАП 3. Полный протокол старой диагностики (для сравнения)
1. Залей на адаптер ПО-совместимую конфигурацию (2.21.35 как сейчас работает
   или после восстановления из бэкапа).
2. Запусти USBPcap на хаб адаптера, ВЫПОЛНИ реальную диагностику автомобиля
   (выбери ЭБУ, соедини) 30–60 секунд, останови снифф.
3. Пришли pcapng — в нём будут настоящие BOT-команды диагностики (в предыдущем
   трейсе была только фаза простоя: TEST_UNIT_READY/SENSE каждые 0.75с).

### ЭТАП 4. (Опционально) Снимок серийной области клона
```
J-Link> savebin eeprom_page.bin, 0x08002800, 0x800
J-Link> savebin eeprom_pageB.bin, 0x08003000, 0x800
```
Пришли оба файла (в них серийник/калибровка клона и метаданные CRC stage2).

## ПРАВИЛА БЕЗОПАСНОСТИ
- НИКОГДА не продолжай (`g`) с оставленным софт-BKPT (0xBE00) в flash:
  перед `g` проверяй `mem16 <адрес BP>, 1` — если видишь 0xBE00 и не хочешь
  остановки — перезалей этот halfword оригиналом.
- ClrBP принимает HANDLE из SetBP (1, 2, 3...), не адрес.
- Все savebin делай при останованном ядре (h).
- Перед любыми экспериментами — бэкап Этапа 0.
