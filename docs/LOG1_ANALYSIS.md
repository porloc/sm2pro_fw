# Анализ лога №1 — прошивка SM2Pro_full_flash_2.22.3_patched.bin (v1)

Файл: USBPcap-захват (pcapng), 1.9 МБ, 29636 пакетов, длительность **51.485 с**.
Захвачено 3 USB-шины. Разобрано скриптом `scripts/parse_usbpcap.py` (0 ошибок разбора).

## Топология шины

| Шина | Устройства |
|------|-----------|
| bus=1 (WCH-контроллер) | хаб 1A86:809D, клавиатура Genius 0458:0170, флешка 1908:0226, CH340 1A86:5394, **адаптер 20A2:0001 (dev=6)** |
| bus=2 (Intel) | хаб 8087:0029, веб-камера 13D3:56A8 |
| bus=3 | пусто |

## ГЛАВНЫЙ РЕЗУЛЬТАТ

**За всю запись (51,5 с) с адаптером не обменялись ни одним байтом.**

Все пакеты, адресованные адаптеру (bus=1 dev=6) — ровно 6 штук, все в момент
`t = 0.000000` (перечисление шины при старте USBPcap-захвата):

```
#1  GET_DESCRIPTOR(DEVICE)  SETUP
#2  COMPLETE 18 байт  → VID=0x20A2 PID=0x0001 class=0xFF iSerial=0
#3  GET_DESCRIPTOR(CONFIG)  SETUP
#4  COMPLETE 32 байт  → 2 bulk-эндпоинта 0x81 IN / 0x02 OUT, 64 байта
#5  SET_CONFIGURATION  SETUP
#6  COMPLETE
```

Дальше — **полная тишина до конца записи**:

- 0 bulk-пакетов в любую сторону;
- 0 управляющих (control) запросов к устройству;
- 0 повторных перечислений — адаптер не отключался, не зависал, не перезагружался
  все 51 секунды;
- ни одного URB со статусом ошибки.

Дескрипторы в точности совпадают с **bootloader-набором** из нашего анализа дампа
(class 0xFF, VID 0x20A2 PID 0x0001, bcdDevice 0x0100, 2×bulk 64B) — т.е. адаптер
всё время находился в режиме bootloader. Команда 0x88 (ARM → запуск stab 0x08004000)
не подавалась ни разу.

## Контроль корректности захвата

Чтобы исключить «захват ничего не ловил»:

- флешка 1908:0226 — виден SCSI-опрос (пакеты `55 53 42 43` «USBC» CBW/CSW)
  каждые ~0,74 с всю запись;
- CH340 (1A86:5394) — 386 INTR-опросов драйвера;
- веб-камера на bus=2 — поток до t≈45,8 с;
- клавиатура Genius — непрерывный INTR-поток.

Т.е. USBPcap исправно ловил трафик **всех** драйверов на этой шине. Если бы
программа прошивки обменялась с адаптером хотя бы одним пакетом — мы бы это видели.

## Возможные объяснения (по убыванию вероятности)

1. **Попытка прошивки была сделана до старта захвата** (или после остановки) —
   в лог она не попала. При старте USBPcap переустанавливает фильтр и
   пере-перечисляет шину; если программа уже была запущена/подключена, её сессия
   была бы оборвана именно в t=0.
2. **Программа запускалась во время захвата, но не смогла открыть устройство** —
   ошибка выдана на этапе открытия `\\.\SmUsb000` без единого обращения к USB.
   Причины: драйвер smndis не привязался/не перезапустился после пере-перечисления
   (в т.ч. возможный конфликт NDIS×USBPcap-фильтр — известная проблема USBPcap),
   драйвер отсутствует/сломан, либо в программе выбрано не то устройство.
3. «Обмен ушёл мимо захвата» — **исключено**: адаптер физически на bus=1, его
   перечисление поймано, весь остальной трафик этой шины ловится.

## Ключевое следствие

Если во время этого захвата на экране появился код **[0007]** — значит этот код
может формироваться **без единого байта обмена с прибором**, т.е. это код
«не удалось начать обмен/открыть устройство», а не ответ прибора.

Тогда возможно, что **ни одна из наших тестовых прошивок (v1=[0007], v2/PROBE/
MODE1=00000) вообще не дошла до адаптера**, а разница между ошибками — на стороне
ПК (разное состояние драйвера/программы в момент попытки), а не прошивки.

## Хорошая новость

Bootloader адаптера жив и стабилен: корректные дескрипторы, успешное
SET_CONFIGURATION, ни одного disconnect'а и ни одной ошибки на шине за 51 секунду.
Железо (кварц, USB-физика, питание) — в порядке.

## Следующие шаги

**A. Без захвата (5 минут):** Диспетчер устройств → найти адаптер (VID 20A2,
PID 0001) → убедиться, что на нём висит драйвер SM2/SmUsb (сетевой адаптер
SmUsb000), сделать скриншот ветки. Желтый восклицательный знак = драйвер не встал.

**B. Повторный захват со строгим порядком:**
1. Старт захвата → подождать 2 с;
2. **Переткнуть адаптер** — в логе должно появиться НОВОЕ перечисление
   (доказательство, что захват живой);
3. Запустить программу прошивки, воспроизвести ошибку;
4. Подождать 3 с → стоп захвата;
5. Записать точно, какой код/текст ошибки был на экране.

**C. «Золотой» захват (эталон):** образ donor 2.21.32 + старый софт 2.21.32 —
успешное подключение/работа. Валидирует всю цепочку (USBPcap × smndis × софт)
и даёт эталонный протокол обмена для сравнения.
