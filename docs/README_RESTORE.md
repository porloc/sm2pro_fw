## Как происходит обновление прошивки (из реверса бутлоадера)

Устройство всегда стартует в бутлоадер (режим моста USB↔USART2). Протокол — пакеты
`[cmd:1][len:2][pad:1][data:len]` по vendor-specific USB (VID 0x20A2 / PID 0x0001).

| Команда | Действие |
|---------|----------|
| `0x83`  | GET INFO: серийник (из 0x08000180), 16 EEPROM-слов, состояние |
| `0x80`  | ERASE/START UPDATE: data = `[seed(4)][crc(4)][ver(4)=0x1070][size(4)]` + 16 конфиг-полуслов в EEPROM; стирает страницы с 0x08004000 до 0x08004000+size; отвечает размером блока (2048) |
| `0x81`  | WRITE BLOCK: ровно 2048 байт **зашифрованных** данных, пишутся с 0x08004000 подряд |
| `0x82`  | END: блокировка флеша, state=0 |
| `0x88`  | LAUNCH APP: state→2, главный цикл прыгает на 0x08004000 (VTOR+MSP+PC) |
| `0x87`  | JUMP SYSTEM BOOTLOADER (0x1FFFB000 — родной DFU/UART загрузчик STM32) |
| `0x89`  | UART-транзакция (мост J2534): подкоманды 1/2/4 — скорость/чётность USART2, 3 — приём-передача с таймаутами |

### Шифрование блоков записи (поточный шифр, слово за словом)

```
A = 0xCAFE1381                       # константа (DAT_08001188)
B = seed                             # приходит в erase-пакете, у SM2 = 0x7821AB35
K1 = 0x13AB3377, K2 = 0x5188016B     # ключи в бутлоадере (0x0800118C/0x08001190)

для каждого 32-битного слова w (LE) зашифрованного блока:
    plain = ROR32( ((((w - A) & 0xFFFFFFFF) ^ K1) + 2*B ^ B) - 8*B , 17 )
    B = (B + A*8) & 0xFFFFFFFF;  B ^= B >> 1
    A = (ROR32(w, 7) ^ A) + K2
```

Приложение в `sm2lib.dll` хранится **уже зашифрованным** и отсылается как есть.
Расположение в `sm2lib.dll` (v2.21.32): смещение **0x40080**, размер **0xB2E0**,
seed **0x7821AB35**; ожидаемый CRC32(STM32) = **0xBDEE4E94** — совпадает с
расчётным по расшифрованному образу (проверено).

### Проверка целостности при старте

Если в EEPROM (страница 0x08002800, слоты 0–5) записаны `crc/ver/size`, бутлоадер
считает аппаратный CRC32 (блок CRC 0x40023000) области приложения. У донорского
дампа эти слоты пусты (0xFF) → проверка отключена. В собранном образе приложение
официальное, CRC = 0xBDEE4E94 (валиден в любом случае).

## Найденное отличие донорского дампа от официальной прошивки

В донорском `.bin` ровно **одно** слово отличается от официального образа:
`0x0800E958`: `0x080028E8` вместо `0x1FFFF7E8`. Это «мёртвая» (ни разу не
используемая) ячейка пула литералов — на работу не влияет, но CRC из-за неё
не совпадал (0xA8264A10 ≠ 0xBDEE4E94). Похоже на метку/патч производителя
клона. В восстановленном образе — официальное слово, CRC валиден.

## Инструкция по прошивке

### Вариант 1 — SWD (рекомендуется, если бутлоадер битый)

1. Подключить ST-Link (или J-Link/OpenOCD-адаптер) к площадкам SWDIO(PA13),
   SWCLK(PA14), GND, 3V3 платы адаптера.
2. В STM32CubeProgrammer: подключиться SWD. Если стоит Read-Out Protection —
   сначала «Option Bytes → RDP → AA (unlock)» (сотрёт флеш — это ок).
3. Open → `SM2Pro_full_flash_2.21.32_restored.bin`, адрес **0x08000000**, Verify, Program.
4. Питание выключить/включить. Устройство определится как USB VID:0x20A2 PID:0x0001.

CLI (openocd):
```
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
        -c "init; reset halt; flash write_image erase SM2Pro_full_flash_2.21.32_restored.bin 0x08000000; reset run; exit"
```
CLI (st-flash):
```
st-flash --format binary write SM2Pro_full_flash_2.21.32_restored.bin 0x08000000
```

### Вариант 2 — системный UART-загрузчик STM32 (если SWD недоступен)

1. BOOT0 → 1 (джампер/резистор на плате), подать питание.
2. UART: PA9 (TX) / PA10 (RX), 57600 8E1 (AN2606, USART1).
3. Прошить через `stm32flash`:
```
stm32flash -w SM2Pro_full_flash_2.21.32_restored.bin -v -g 0x0 COM3
```
4. BOOT0 → 0, перезапустить питание.

### После прошивки

- Первый запуск: устройство ждёт в режиме бутлоадера; ПО Scanmatik при
  подключении само отправит команду запуска приложения (0x88) либо обновит
  прошивку штатным путём.
- Серийный номер устройства станет A111788 (из донорского бутлоадера). Все
  настройки EEPROM донора сохранены; при желании чип можно очистить в 0xFF
  в диапазоне 0x08002800–0x080037FF — приложение само восстановит умолчания.

## Замечания по защите

- Опция чтения (RDP) в собранном образе не задаётся — опциональные байты
  остаются как есть на чипе.
- 128-байтный блоб по 0x08000184 и данные 0x0800F2E0–0x0800F7FF прошивкой не
  читаются (заводские данные, сохранены для совместимости).
