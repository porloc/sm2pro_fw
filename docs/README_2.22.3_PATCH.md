# Прошивка 2.22.3 из ПК-программы Scanmatik 2.22.3 + аналогичный патч клона

## Что сделано

Из дистрибутива `Scanmatik2.22.3.zip` (тот же Google Drive, файл
`sm2lib.dll` 525 432 байта) извлечена прошивка SM2 (типы устройств 1/2/3),
дешифрована тем же потоковым шифром бутлоадера, проверена по CRC и собран
полный образ флеша 256 КБ с патчем, аналогичным найденному в донорском
дампе 2.21.32 (перенаправление чтения UID из системной памяти в EEPROM).

## Где лежала прошивка и как извлечена

Параметры зашиты в коде `sm2lib.dll` 2.22.3, функция заполнения структуры
обновления **VA 0x1000C760** (в 2.21.32 — immediates в коде около file 0xA3A0).
Для SM2 заполняются **две** записи по 0x1C байт: `{seed, ver, size, crc, ptr_осн, ptr_доп1, ptr_доп2}`:

| Поле | Запись 1 (stub) | Запись 2 (приложение) |
|------|-----------------|----------------------|
| seed | 0x7821AB35 (как в 2.21.32) | 0x7821AB35 |
| ver  | 0x1198 (в 2.21.32 было 0x1070) | 0x1198 |
| size | 0xB00 | 0x1353C |
| crc  | 0x2912D0A0 | 0x210E9A13 |
| блоб (VA → file) | 0x100594F8 → 0x57EF8 | 0x10045FB8 → 0x449B8 |
| доп1 (0x20 байт, cmd 0x8B) | 0x10059FF8 | 0x10045F98 |
| доп2 (0x48 байт, cmd 0x8B) | 0x1005A018 | 0x10045F50 |

Шифр прежний (константы K1=0x13AB3377, K2=0x5188016B, A=0xCAFE1381,
B=seed — подтверждены и в коде stub-загрузчика на 0x0800432E–0x08004378).
CRC32(STM32) обеих записей **сошлись**: 0x2912D0A0 и 0x210E9A13.

Для Type 5 (SM3): seed 0x43719874, size 0xF2CC, crc 0x83BBF98A, блоб
0x1005A060 (в данной задаче не используется).

## Новая архитектура прошивки (главное отличие от 2.21.32)

Обновление теперь **двухступенчатое**:

```
Этап 1 (протокол бутлоадера 0x80/0x81/0x82, + новая 0x8B):
  0x80 ERASE  [seed][crc][ver][size=0xB00] -> стирает с 0x08004000
  0x81 WRITE  блоки по 2048 байт (шифр непрерывный)
  0x82 END
  0x8B (только если бутлоадер ответил 0x18/1) — 0x68 байт доп. данных
  => записывается ЗАГРУЗЧИК-СТАБ (0xB00) по адресу 0x08004000

Этап 2 (протокол stub-загрузчика 0x33/0x34/0x35/0x36):
  0x33 ERASE  [seed][crc][ver][size=0x1353C] -> стирает с 0x08005000
  0x34 WRITE  блоки по 2048 байт (тот же шифр, то же семя)
  0x35 END    + проверка CRC32 приложения (сервис бутлоадера, опкод 9)
  0x36 LAUNCH пакет из 3-х слов (идентификация прибора) -> state=2
  => записывается ОСНОВНОЕ ПРИЛОЖЕНИЕ (0x1353C) по адресу 0x08005000
```

Цепочка запуска: бутлоадер (0x08000000) → stub (0x08004000) → приложение
(0x08005000, VTOR=0x08005000, переход в 0x08004190 stub'а). Stub вызывает
сервисы бутлоадера через таблицу по [0x0800017C] (14 сервисов, опкоды
0/1/3/4/9/13) — **донорский бутлоадер 2.21.32 полностью совместим**, менять
его не нужно. USB (VID 0x20A2 / PID 0x0001) обслуживает бутлоадер —
идентификация прибора ПК-программой не меняется.

Проверка целостности: бутлоадер проверяет CRC при старте только если в
EEPROM (страница 0x08002800, слоты 0–5) записаны crc/ver/size — в донорском
EEPROM они пусты (0xFF), проверка выключена. Stub проверяет CRC приложения
**только в процессе обновления** (команда 0x35); при запуске приложения
никакая CRC не проверяется — запатченный образ стартует штатно.

## Патч клона (аналог слова 0x0800E958 в 2.21.32)

В 2.21.32 донор отличался от официальной прошивки одним словом 0x0800E958
(`0x1FFFF7E8` → `0x080028E8`): обработчик команды 0x12 (challenge/response
аутентификация) читал «UID» из EEPROM вместо аппаратного UID кристалла.

В 2.22.3 защита усилена: адрес аппаратного UID **0x1FFFF7E8** встречается
в приложении **9 раз** — в пулах литералов девяти участков кода (все
загружаются инструкцией `ldr rX, [pc, #imm]`, укладываются в стек и
используются в общем обфусцированном обработчике протокола с «плоским»
управлением — диспетчер 0x0800C2CA, переход `mov pc, r6` через таблицу).
Старых констант аутентификации (0x3EA816AB и др.) в новой прошивке и в
новых ПК-библиотеках нет — схема заменена.

Аналогичный патч: во **всех 9 словах** значение `0x1FFFF7E8` заменено на
`0x080028E8`. Устройство везде (во всех командах, сообщающих UID/отпечаток)
читает «виртуальный UID» из EEPROM — ровно тот же приём, что у производителя
клона, с сохранением данных донора в EEPROM:

```
0x080028E8: слово 0x3247F69E   (байты 9E F6 47 32)
0x080028F3: байт  0x43
остальное до 0x080028F4: 0xFF
```

Список запатченных адресов (слово в пуле литералов):
`0x0800C520, 0x0800D5C8, 0x0800D998, 0x0800DD7C, 0x0800E15C, 0x0800E700,
0x0800EACC, 0x0800EEA4, 0x0800F950` (в файле приложения: +0x7520, +0x85C8,
+0x8998, +0x8D7C, +0x915C, +0x9700, +0x9ACC, +0x9EA4, +0xA950).

Разница между `restored` и `patched` образами — ровно эти 9 слов, больше
ничего. Область бутлоадера+EEPROM (0x00000–0x03FFF) байт-в-байт донорская.

## Прошивка (SWD)

1. ST-Link/J-Link/OpenOCD к SWDIO(PA13), SWCLK(PA14), GND, 3V3.
2. При RDP-защите: Option Bytes → RDP → 0xAA (сотрёт флеш — нормально).
3. Залить `SM2Pro_full_flash_2.22.3_patched.bin` по адресу **0x08000000**:

```
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
        -c "init; reset halt; flash write_image erase SM2Pro_full_flash_2.22.3_patched.bin 0x08000000; reset run; exit"
# или
st-flash --format binary write SM2Pro_full_flash_2.22.3_patched.bin 0x08000000
```

4. Питание перезапустить. Устройство поднимется в режиме stub
   (USB VID:0x20A2 PID:0x0001), ПК-программа **Scanmatik 2.22.3** при
   подключении сама отправит команду запуска (0x36) и переведёт в рабочее
   приложение. Использовать ПО 2.22.3 из этого же дистрибутива.

## Важные замечания

- **Не обновлять прошивку через ПК-программу после заливки патченного
  образа** — штатное обновление перезапишет приложение официальным
  (непатченным) образом и патч сотрётся (устройство перейдёт на чтение
  аппаратного UID; это не «кирпич», просто вернётся официальное поведение).
- В отличие от 2.21.32, точную формулу нового отпечатка UID подтвердить
  нельзя — код приложения обфусцирован (плоское управление, таблицы
  переходов), а константы 2.21.32 из новых бинарников исчезли. Патч
  семантически идентичен: все 9 точек чтения UID перенаправлены в EEPROM,
  значения детерминированы и одинаковы для всех приборов с этим дампом.
- Если ПК-программа 2.22.3 при подключении сама предложит «обновить
  прошивку» (например, не распознав версию 0x1198) — отказаться, иначе
  патч будет затёрт.
- Бутлоадер, серийный номер (A111788), крипто-блоб 0x08000184 и EEPROM —
  донорские, не изменялись; совместимость stub↔бутлоадер проверена по
  таблице сервисов [0x0800017C] (все используемые опкоды 0/1/3/4/9/13
  существуют в донорском бутлоадере).
